# 주요 기능 릴리스 체크리스트

사용 흐름·정책·설치 방법·지원 플랫폼에 영향을 주는 변경은 웹 배포나 네이티브 릴리스 전에 확인합니다. 기능 브랜치에서 운영 웹을 수동 배포할 때도 같은 기준을 적용합니다. 사용자 설명이 바뀌지 않는 내부 수정은 PR에 변경 불필요 이유만 남깁니다.

- [ ] [English](../README.md) · [한국어](../README.ko.md) · [日本語](../README.ja.md)를 함께 갱신했습니다. 소개·대표 화면·실행 링크는 상단에 두고, 바뀐 사용 흐름이나 지원 상태는 해당 설명에서 수정했습니다.
- [ ] 운영 웹 배포, GitHub 소스, 공개 설치본, 로컬 시험 설치를 구분했습니다. 웹에서 배포되는 화면과 새 APK·EXE가 필요한 변경을 분리하고, 아직 공개하지 않은 버전은 공개 설치본으로 적지 않았습니다.
- [ ] 세 언어의 기능 범위와 주의사항이 일치합니다. 소개·스크린샷·설치 링크가 실제 배포와 맞는지 확인했으며, 예시 화면과 실기기 검증 결과를 구분했습니다.
- [ ] `npm.cmd run docs:check`, `node --test apps/web/test/readme.test.mjs`를 실행하고 바뀐 링크를 직접 확인했습니다. 제품 변경은 별도의 프로젝트·플랫폼 검증도 수행했습니다.
- [ ] 릴리스 PR에 배포·릴리스 또는 검증 기록을 연결했습니다. 사소한 수정이나 운영 상세는 README에 쌓지 않고 [진행 상태](../memory-bank/progress.md), 검증 문서, 릴리스 노트 중 맞는 곳에 남겼습니다.
