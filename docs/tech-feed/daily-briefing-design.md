# 기술 피드: 자동 분류·오늘의 브리핑·읽기 UX 설계

작성일: 2026-09-14. 상태: 구현·검증 및 2026-09-15 운영 배포 완료. 실행 계획: `daily-briefing-implementation.md`, 검증 근거: `daily-briefing-verification.md`.

## 1. 목표와 승인 범위

미분류와 원시 마크다운을 줄이고, 자유 입력 관심 설정을 중심으로 피드를 단순화한다. 오늘 수집한 내 피드의 통계는 자동 표시하고, AI 인사이트는 명시적인 버튼 요청으로 생성하여 재사용한다.

- 기존 Vite/React, Supabase, 무료 OpenRouter 클라이언트, DeepL 번역 구조를 유지한다.
- 타이머·출석·회복루틴·로그인 경로를 변경하지 않는다. 브리핑 실패가 이 기능들을 잠그지 않는다.
- 전체 인터넷의 추세, 기사 전문·영상 내용 분석, 유료 자동 전환, 외부 알림은 범위 밖이다.
- 기존 검색 월900회, DeepL 월450000자, 코칭과 공유하는 사용자별 AI 실제 호출6회/일 정책을 유지한다. 분류 규칙·통계·캐시 조회는 AI 호출을 사용하지 않는다.

## 2. 확인된 현재 구조

- `tech-feed-core.mjs`의 summarizeBatch는 AI 요약 성공 시에만 category를 기록한다. 요약 대기·근거 부족·분류 응답 누락이면 null이 유지된다.
- `TechFeedSection.tsx`는 null category를 미분류로 출력한다. feedExcerptView는 문자열을260자로 자르고, cleanFeedIntroduction은 줄바꿈을 공백으로 합쳐 제목/문단 구조가 사라진다.
- 수집 prompt, 고정 관심 체크박스, 목록의 고정 관심 필터가 동시에 존재한다. 백엔드는 현재 목록에 있지만 임의의 관심 주제를 모두 표현하지 못한다.
- 현재 목록은20개 커서 페이지다. 서버에는 기사 최초 discovered_at, 구독 출처, 관심 검색문과 기사 매핑이 있다. 개인별 최초 도착 시각 이력은 없다.
- 공개 글과 AI 성공 결과는 공용이고 구독·저장·할 일 연결은 사용자별이다. 기존 개인 가시성 규칙은 확장 API에도 동일하게 적용해야 한다.

## 3. 글 분류와 기술 주제 태그

### 콘텐츠 유형

기존 DB enum을 유지하고 표시 이름을 정리한다.

| 값 | 표시 | 판단 근거 예 |
| --- | --- | --- |
| news | 기술 소식 | 버전 출시, 기능 발표, 변경 공지 |
| practice | 실무·튜토리얼 | 구현 절차, 코드 예제, 사용 가이드 |
| deep_dive | 사례·심층 분석 | 도입 사례, 설계 근거, 실험/장애 분석 |

- 분류를 요약 호출과 분리한다. 제목과 실제 소개의 한·영 표현을 이용하는 보수적 규칙을 먼저 사용한다. 분류를 위해 별도 AI 호출을 추가하지 않는다.
- 기존 유효한 AI 분류를 보존한다. 규칙 결과에는 method와 rules_version을 함께 기록하고, 추후 유효한 AI 분류가 생기면 이를 우선한다.
- 충돌하거나 근거가 부족하면 null을 유지하되 카드에 미분류 배지를 반복 표시하지 않는다. 통계에는 분류 근거 부족 건수를 명시한다. 모든 글을 억지로 세 유형에 넣지 않는다.
- 영상 여부는 콘텐츠 유형과 별개다. 영상이라는 이유만으로 심층 분석으로 분류하거나 영상 내용을 추론하지 않는다.
- 새 글과 보관 중인 기존 글에 적용한다. 기존 글은 배치당 최대50개씩, 작업 잠금과 버전 기준으로 처리하여 반복 전체 스캔을 피한다. 웹 목록에도 동일한 순수 규칙 fallback을 적용하여 백필 대기 중 표시를 개선한다.

### 기술 주제

- 콘텐츠 유형과 주제(AWS, 백엔드, 특정 제품명 등)를 분리한다.
- 실제 제목·소개에 근거가 있는 기술 용어/별칭과 사용자의 관심 문구에서 추출한 검색 단위를 대조한다. 문구를 입력했다는 이유만으로 모든 기사에 그 태그를 붙이지 않는다.
- 기존 고정5개 분야는 호환 메타데이터로 보존하되 새 필터 선택지를 제한하지 않는다. 입력한 사용자 용어도 실제 글과 일치하면 필터 후보가 된다.
- 공용 기술 태그와 개인 관심 일치 결과를 분리한다. 개인 prompt 전체를 공용 기사 태그에 저장하지 않는다. 태그는 짧게 표시하고 카드에는 최대3개만 우선 표시한다.
- 태그를 알 수 없는 글은 전체 목록에서 계속 읽을 수 있다.

## 4. 본문 가독성

- 저장된 원문/번역은 보존한다. 표시 계층에서 안전한 마크다운 부분집합을 파싱한다.
- 미리보기: 제목 기호, 강조 기호, 링크 문법 등을 평문으로 정리한 뒤260자로 자른다. 코드·단어 속 C#, #include, URL fragment는 무조건 제거하지 않는다.
- 펼친 내용: 제목, 문단, 순서/비순서 목록, 강조, 인라인 코드와 코드 블록을 구분한다. 원래 데이터에 줄바꿈이 없으면 구조를 만들어내지 않는다.
- 원시 HTML은 실행하지 않고 텍스트로 처리한다. 외부 이미지/iframe 마크다운은 렌더링하지 않는다. 미디어는 기존 검증된 미디어 컴포넌트를 사용한다.
- 본문 링크는 HTTPS/HTTP 안전 URL 검증과 새 창 noopener/noreferrer를 적용한다. javascript/data URL을 차단한다. 원문 출처 링크는 서버 기사 URL을 유지한다.
- 기존 시간표·홍보 문구 제거와 영상 소개 제한은 유지하되 문단을 합치는 함수와 구조 보존 렌더링을 분리한다.
- 모바일390px에서 긴 URL·코드가 가로 화면을 밀어내지 않게 한다. 펼치기 버튼의 접근성 상태와 초점 동작을 유지한다.

## 5. 관심 설정과 필터

- 수집 설정의 주 입력은 `내 관심 소식 설정` 자유 문구 하나로 한다. 구독 출처 선택/RSS 추가는 고급 수집 설정으로 접는다.
- 기존 고정 관심 체크박스를 활성 화면에서 제거한다. 기존 값은 삭제하지 않으며 새 흐름에서 자유 입력 결과를 숨기는 추가 수집 조건으로 쓰지 않는다.
- `모아둔 글 필터`를 기본 접힘으로 배치한다. 주제는 현재 계정의 전체 조회 가능 범위에서 나온 동적 태그, 출처는 실제 구독 이름/웹 원문 도메인이다. 현재 페이지20개에서만 옵션을 만들지 않는다.
- 필터는 수집 조건을 바꾸지 않는다. 선택 중인 조건과 결과 수, 초기화 액션을 표시한다. 최신/저장 모두 선택 조건을 일관되게 적용한다.
- 긴 관심 prompt를 카드 해시태그로 그대로 반복하지 않는다. 저장 원문은 설정 화면에서만 그대로 편집한다.
- 필터 변경 시1페이지로 이동하고 오래된 조회 결과를 버린다. 페이지 캐시 키에 필터를 포함한다.

## 6. 오늘의 기술 브리핑

### 집계 범위와 날짜

- 서버의 계정 time_zone으로 오늘00:00부터 다음날00:00까지를 UTC 범위로 변환한다. 날짜/시간대는 임의 사용자ID와 함께 클라이언트가 지정할 수 없게 한다.
- 현재 계정의 최신 피드 가시성에 해당하고 기사 discovered_at이 이 범위에 있는 글을 article_id/기존 정규화 URL 기준으로 중복 제외한다. 발행일은 오늘 판정에 쓰지 않는다.
- UI에 `오늘 수집된 내 피드 · 최초 수집 시각 기준`을 표시한다. 예전에 공용으로 수집한 글이 오늘 새 관심 설정에 연결된 것까지 오늘 신규 수집으로 재계산하지 않는다. 개인별 첫 도착 이력 도입은 이번 범위가 아니다.
- 저장함, 목록 페이지, 임시 필터에 따라 브리핑의 모집단을 바꾸지 않는다. 관심/구독 변경은 현재 가시성을 바꾸므로 다시 집계한다.
- 전체 건수, 출처 수, 유형별 건수, 주제별 건수를 서버에서 집계한다. 여러 주제를 가진 글은 중복 집계될 수 있음을 표시하며 주제 건수 합계를 전체 글 수로 오해하게 하지 않는다.
- 첫 진입과 명시적 새 글 확인 완료 후 통계를 재조회한다. 화면을 보고 있는 동안 불필요한 폴링이나 추가 수집을 유발하지 않는다. 날짜 경계/시간대 변경뿐 아니라 같은 날 창 재활성화에도 읽기 전용 통계를 갱신한다. focus/visibility 중복 이벤트는 합치며 진행 중 AI 생성을 취소하거나 새로 생성하지 않는다. 같은 계정·같은 날짜 재조회 실패 시 마지막 통계는 유지하고 확인 실패를 표시하되, 권한을 확인할 수 없는 인사이트는 숨긴다.

### AI 생성과 근거

- `오늘 요약 보기`를 누르면 서버가 현재 대상 스냅샷을 확정한다. 같은 유효 스냅샷 성공 결과는 즉시 반환하고 AI를 다시 호출하지 않는다.
- 생성 결과는 한국어 핵심 흐름 최대3개, 각 흐름의 읽을 이유/공부 관점, 각 항목의 근거 article_id1~3개다. 결과 URL은 AI가 아니라 서버가 ID로 매핑한다.
- 빈 결과 또는 요약 가능한 소개가2개 미만이면 AI를 호출하지 않고 건수·기사 링크와 근거 부족 상태를 제공한다.
- 요약 허용된 실제 소개160자 이상인 비영상 글에서 출처별 round-robin으로 최대24개를 고른다. 같은 출처 안에서는 최초 수집 최신순/id순으로 결정하며 소개는 글당2000자로 제한한다.
- 전체 통계는 전부 집계하되 AI가 읽은 건수는 별도로 표시한다. 예: 전체 N건 중 소개가 충분한24건 분석. 일부 대표 글의 경향을 전체 업계 추세로 확대하지 않는다.
- AI에 기사 ID·제목·실제 소개·서버 집계만 전달한다. 계정ID, 이메일, 개인 관심 prompt는 전달하지 않는다. 외부 글의 지시는 데이터로만 취급한다.
- AI가 반환한 근거 ID가 입력에 없거나 필드/길이 검증에 실패하면 전체 결과를 실패 처리한다. 추측한 숫자 대신 통계 숫자는 서버에서 표시한다.

### 캐시·예산·실패

- 캐시는 사용자+현지 날짜+시간대+현재 대상 ID/내용 해시+분석기 버전으로 분리한다. 첫 버전의 일일 브리핑 결과는 사용자 간 공유하지 않는다. 기존 공용 기사 요약/번역은 계속 재사용한다.
- 새 글/내용 변경으로 스냅샷이 달라지면 `새 글이 추가됐어요 · 요약 갱신`을 표시한다. 기존 결과를 생성 시각/분석 범위와 함께 유지하고 버튼을 눌러야 다시 AI 호출한다.
- 기존 내용이 구독 해제/권한 변경으로 보이지 않게 된 경우 그 내용을 포함한 낡은 결과를 표시하지 않는다. 생성 전과 저장/반환 전에 가시성을 재검증한다.
- 같은 계정·날짜의 동시 생성은 DB lease로 합치고 유효 lease만 결과를 저장한다. 외부 AI 호출은 DB 트랜잭션 밖에서 수행한다.
- 실제 제공자 요청 직전에 기존 공유 AI 할당량을 원자적으로 예약한다. 호출 실패도 차감하며 캐시 적중·생성 중 중복 요청·근거 부족은 차감하지 않는다.
- AI 응답 기한20초, 요청 전체 상한30초, lease90초. 실패 후 재시도는 명시적 버튼으로만 수행하고 유료 fallback은 없다. 화면 이탈/계정 전환 시 늦은 결과를 버린다.
- 한도 초과·제공자 장애·근거 부족은 각각 구분한다. 실패해도 통계, 기존 접근 가능한 캐시, 기사 목록은 남는다. 수신 중지/전역 피드 중지 중에는 새 AI 생성도 하지 않는다.
- 캐시는90일 보관 후 기존 정리 경로에서 소량 배치 삭제한다. 새로운 빈번한 cron을 만들지 않는다.

## 7. 구현 경계

- 순수 공용 모듈: 콘텐츠 유형/태그 규칙, 버전, 문서 표시 모델. 웹·Edge·테스트가 동일 규칙을 사용한다.
- 서버 집계/가시성: 목록·필터 후보·브리핑 대상 선정에 같은 가시성 조건을 사용한다. 서비스 역할 전용 RPC의 user_id는 인증된 API가 주입하고 브라우저 입력을 신뢰하지 않는다.
- 추가형 migration: 분류 메타데이터/버전, 필요한 주제 인덱스, 개인별 브리핑 스냅샷·상태·lease·결과. 기존 기사/저장/할 일 데이터를 삭제하거나 기존 migration을 수정하지 않는다.
- 개인 브리핑 테이블은 RLS 소유자 SELECT만, 생성/완료/할당량 RPC는 service_role 전용. 다른 계정의 스냅샷/캐시가 재사용되거나 열거되지 않게 한다.
- 기존 `tech-feed` API에 필터 후보·브리핑 조회·생성 액션을 추가한다. 통계 조회로 생성이 시작되지 않게 분리한다.
- 기존 worker에 제한된 분류 백필만 추가한다. AI 일일 브리핑은 cron 자동 실행 대상이 아니다.
- 웹: FeedArticleCard/TechFeedSection에 모든 로직을 늘어놓지 않고 본문 표시, 동적 필터, 오늘 브리핑을 작은 컴포넌트로 분리한다.
