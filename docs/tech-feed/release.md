## 관심 입력·웹 검색 추가 릴리스 — 구현 및 검증 중

이 절은 아래 이전 파일럿 전용 설명의 후속 개정입니다. 실제 반영 여부는 `memory-bank/progress.md`를 확인하며, 문서만으로 운영 활성화를 판단하지 않습니다.

- 신규 마이그레이션: `20260912150427_tech_feed_web_search.sql` (운영 적용 버전). 기존 두 피드 마이그레이션을 재적용하지 않습니다. 개인 설정·공유 주제/캐시·월간 사용량을 추가하며 기존 데이터를 삭제하지 않습니다. 적용 현황은 `deployment-20260913.md`에서 확인합니다.
- `TECH_FEED_ACCESS_MODE=self_service`: 인증된 사용자가 웹에서 관심 내용과 수신을 직접 설정합니다. 계정별 환경 변수 등록이 필요하지 않습니다. 기본값/다른 값은 기존 pilot 모드를 유지합니다.
- `TECH_FEED_ENABLED=false`: 수집 전체를 멈춥니다. self_service의 관심 내용 저장과 기존 저장 자료 접근까지 없애는 스위치가 아닙니다. 출석·타이머 기능과 분리합니다.
- `TAVILY_API_KEY`: 앱 전용 무료 키를 Edge Secrets에만 저장합니다. 미등록이면 검색 요청을 하지 않습니다. 일반 사용자에게 키를 입력받지 않습니다.
- `TECH_FEED_SEARCH_MONTHLY_CAP`: 기본900, 상한900, 하한0인 앱 전체 월간 시도 예산입니다.0은 웹 검색만 멈추는 데 사용할 수 있습니다. 실패도 계산하며 계정/키의 실제 무료 잔량도 요청 전 확인합니다.
- 무료 검색 계정 검증과 개인정보 안내: [검색 운영 가이드](search-provider.md). 기존 무료 AI 설정은 별도이며 키/한도가 없으면 실제 소개와 링크를 표시합니다.
- worker의 gateway JWT 설정은 현재 그대로 유지합니다. 현 Cron의 secret 헤더 호출이 게이트웨이를 통과하는 인증 구성은 별도 확인/승인 후 적용하며, 검증 전 예약기를 켜지 않습니다.
- DB → 서버 함수 → 웹 → 인증/제공자/소스 권한 검증 → 수집 활성화 순서입니다. 키 미등록 상태에서도 설정·준비 안내·저장 글 화면은 확인하되 실제 검색 성공으로 보고하지 않습니다.
- 확인: 동일 주제의 두 사용자/동시 마지막 예약/월경계/요약 실패/RSS 독립 처리, 실제 PC·390px 입력·중지·재개·충돌·계정 전환. 로컬 PGlite 검증은 hosted 다중 연결 동시성 실험과 구분합니다.
- 커밋·푸시·운영 반영 승인 대기는 현재 작업 기록을 따릅니다. 아래 과거 배포 결과는 이번 웹 검색 추가 기능의 배포 결과가 아닙니다.

# 기술 피드 출시 안내

## 현재 상태

로컬 구현 및 검증 단계입니다. 이 작업은 커밋·푸시·운영 DB 변경·배포·예약 실행 활성화를 수행하지 않습니다. 과거 운영 배포 기록과 이번 로컬 변경을 구분하세요.

## 출시 전 확인

1. 추천 소스 8개의 현재 RSS/API 주소와 사용 조건을 확인합니다. RSS 제공 사실만으로 재가공을 승인하지 않습니다. 이용 조건 근거 URL·검토 일자·허용 범위(소개 저장, AI 요약, 출처 표기)를 운영 기록에 남깁니다. 불명확하면 `pending` 유지, 거부하면 `blocked` 처리합니다. 사용자 추가 소스도 같은 기준을 적용합니다.
2. 서버의 무료 OpenRouter 설정을 확인합니다. 공유 예산은 실제 호출 6회/사용자/일이며 실패도 계산합니다. 소스 수집 성공과 AI 결과 성공은 다른 지표입니다. 유료 모델·유료 공급자로 폴백하지 않습니다.
3. Supabase Edge 배포 런타임에서 DNS 조회와 IP 고정 TLS 연결을 검증합니다. SSRF 보안을 약화하는 일반 fetch 폴백을 추가하지 않습니다. 런타임이 지원하지 않으면 수집을 중지한 채 해결합니다.
4. 운영 계정/시간대와 소스 권한은 문서에 실값을 기록하지 않습니다. 크롤링 내용은 비신뢰 데이터이며 명령으로 실행하지 않습니다.

## 별도 승인을 받은 후 적용 순서

1. 대상 Supabase 프로젝트를 MCP/CLI로 확인하고 백업·현재 마이그레이션 상태를 점검합니다.
2. 추가형 기술 피드 마이그레이션을 적용합니다. 기존 커리어 데이터와 마이그레이션은 삭제하지 않습니다. 커리어 전용 예약 작업만 중지하고 출석 작업은 유지합니다.
3. `tech-feed`, `tech-feed-worker`, 기존 커리어 URL의 410 응답, 갱신한 Slack handler를 배포합니다. 사용자 API는 인증 사용자를 검증하며, worker는 별도의 `x-tech-feed-secret`을 검증합니다. worker를 예약 HTTP 호출로 사용할 때 게이트웨이 JWT 설정과 secret 검증을 함께 확인합니다.
4. 서버 환경 변수 `TECH_FEED_ENABLED=true`, `TECH_FEED_PILOT_USER_IDS`에 승인한 소유자만 설정합니다. 목록이 비면 허용하지 않습니다. `TECH_FEED_WORKER_SECRET`은 긴 임의 비밀값으로 설정하고 같은 값을 Vault의 `tech_feed_worker_secret`에 저장합니다. 프론트엔드 VITE 환경 변수에 서버 키를 넣지 않습니다.
5. 웹을 배포한 후 비파일럿 차단, 시간대 독립 저장, 소스 미리 보기, 저장, 할 일 날짜·시간 확인, 다른 브라우저 동기화, 로그아웃/계정 전환을 확인합니다.
6. 검토한 소스만 승인한 뒤 별도 기술 피드 Cron을 마지막에 활성화합니다. 구체적인 예약 함수와 Vault 구성은 `backend-report.md` 및 마이그레이션의 운영 주석을 따릅니다. 초기 마이그레이션은 Cron을 활성화하지 않습니다.
7. 브라우저를 닫고 두 번 이상의 예약 주기에서 수집 성공/중복 없음/개별 소스 실패 격리/AI 한도 소진 시 소개 유지/출석 Cron 정상 동작을 확인합니다.

## 중지 및 복구

- `TECH_FEED_ENABLED=false`로 사용자 피드와 worker를 중지하고 기술 피드 Cron만 비활성화합니다. 시간대 저장과 기존 공부 기능은 계속 제공됩니다.
- 피드 테이블을 삭제하거나 출석 Cron·타이머·회고·숲을 되돌리지 않습니다.
- 커리어 복원은 `archive/career-coach/README.md`의 별도 절차이며 플래그 하나로 자동 복원하지 않습니다.

## 로컬 검증과 운영 검증의 경계

- `npm test`, `npm run build`, `npm run test:edge`, `npm run mobile:check`, `npm run docs:check`를 실행합니다.
- `node scripts/serve-tech-feed-fixture.mjs`는 실제 React 컴포넌트와 합성 데이터를 사용합니다. 저장/필터/페이지/UI 오류를 확인할 수 있지만 운영 DB 동기화나 외부 소스 권한, 실제 AI 품질을 입증하지 않습니다.

- 추천 소스가 모두 검토 대기이면 피드가 비어 있는 것이 정상입니다. 승인 없이 샘플 글이나 AI가 만든 뉴스를 실제 수집 결과처럼 표시하지 않습니다.
