# PRD: Android 집중 모드 동기화

> 상태: 2026-09-28 서버·웹·Android 구현, 운영 DB/Edge 및 웹 production 배포와 최종 소스를 반영한 직접 설치 APK 빌드 완료. 실제 휴대폰 방해금지·푸시 검증은 별도로 확인한다.

## 1. Problem

웹에서 공부를 시작한 뒤에도 휴대폰 알림이 집중을 방해한다. 사용자는 웹을 주로 사용하며, 공부 중에는 Android 방해금지를 켜고 `잠시 쉬기`·종료 시 독서실 앱이 켠 방해금지만 해제하고 싶다.

## 2. Target Users

- 독서실 웹에서 공부하고 본인 Android 휴대폰에 기존 Expo 앱을 설치하는 사용자.
- 첫 검증은 본인 기기에 직접 설치하는 APK이며 Google Play 공개는 별도 단계다.

## 3. Goals

- 같은 계정의 서버 세션 상태를 기준으로 Android 집중 규칙을 켜고 끈다.
- 휴대폰에 실제 적용되었는지 확인하고, 미연결·권한 거부·전달 지연을 숨기지 않는다.
- 휴식·종료·세션 기한 만료 후 앱이 만든 규칙만 해제한다.
- 전화·메신저 예외는 사용자가 Android 시스템의 방해금지 설정에서 직접 정하도록 안내한다.

## 4. Non-goals

- 다른 앱 실행 자체를 막는 앱 차단기, 접근성 서비스, 기기 관리자 권한, 우회할 수 없는 잠금.
- 사용자가 수동으로 켜거나 다른 앱이 설정한 방해금지를 끄기.
- iOS 방해금지 제어, 모든 웹 기능의 모바일 이식, Play Store 제출.
- 네트워크·Android 푸시가 끊긴 상태에서도 PC 조작이 휴대폰에 즉시 반영된다는 보장.

## 5. User Stories

- 웹에서 공부를 시작하면 연결된 휴대폰에 집중 규칙이 적용되고 적용 상태를 확인한다.
- `잠시 쉬기`를 누르면 앱이 만든 집중 규칙이 해제되고, 재개하면 다시 적용된다.
- 휴대폰이 오프라인이거나 권한을 잃으면 웹에서 `적용 확인 불가`를 보고 직접 확인할 수 있다.
- 휴대폰에서 공부를 시작·중지한 경우도 같은 서버 상태와 규칙을 사용한다.

## 6. User Scenarios

### Normal Flow

1. Android APK 설치 후 웹과 같은 Supabase 계정으로 로그인한다.
2. Android의 알림 및 방해금지 정책 접근을 각각 설명하고 명시적으로 요청한다. 사용자가 독서실 전용 자동 방해금지 규칙을 승인한다.
3. 앱이 기기를 본인 계정에 등록하고 푸시 토큰을 갱신한다. 초기 릴리스는 기기 1대만 연결한다.
4. 웹 또는 앱의 공부 시작·재개가 서버 세션에 확정되면 해당 기기에 상태 변경 신호를 보낸다. 휴대폰은 신호를 명령으로 신뢰하지 않고 서버의 최신 세션을 조회한다.
5. 활성·비휴식 세션이면 앱 소유 규칙을 켜고 적용 결과를 서버에 확인 기록한다. 웹은 확인된 상태만 `휴대폰 집중 모드 켜짐`으로 표시한다.
6. 휴식·종료·기한 만료 시 같은 경로로 앱 소유 규칙을 해제한다.

### Edge Cases

- 앱 화면이 열려 있으면 실시간 변경 또는 화면 복귀 시 즉시 다시 조회한다. 앱이 백그라운드/종료 상태면 푸시 기반 백그라운드 작업으로 재조회하되, Android가 전달·실행을 보장하지 않는다.
- 늦게 도착한 푸시는 현재 서버 세션과 변경 버전을 다시 조회해 오래된 `켜기` 명령을 적용하지 않는다.
- 기기 오프라인·재부팅·앱 강제 종료·로그아웃·권한 철회·서버 장애 시 마지막 확인 시각과 불일치 상태를 표시한다. 기기 복귀 시 재조정한다.
- 세션 lease 만료가 휴식/종료보다 먼저 올 수 있으므로 서버의 만료 상태를 우선한다. 오프라인 상태에서 앱 소유 규칙이 무기한 남지 않도록 로컬 만료 재확인 장치를 설계·실기기 검증한다. Android의 백그라운드 실행 제한 때문에 해제 지연 가능성은 화면에서 고지한다.
- 기기에서 사용자가 직접 방해금지 설정을 변경하면 앱은 자신의 규칙 외의 상태를 덮어쓰지 않는다.

### Error Cases

- 권한 거부: 공부 세션은 정상 시작하지만 `휴대폰 방해금지 미적용`을 표시한다.
- 푸시 실패/미확인: 웹에 적용 성공이라고 표시하지 않는다. 기기에서 앱을 열어 동기화할 수 있게 안내한다.
- 계정 불일치: 다른 계정의 기기·세션을 읽거나 변경하지 않는다.

## 7. Functional Requirements

- [x] Android 네이티브 모듈에서 `NotificationManager`의 앱 소유 `AutomaticZenRule`을 관리한다. Android 15+에서 전역 DND를 직접 변경하거나 모든 DND를 해제하지 않는다. 네이티브 컴파일 통과, 실기기 동작 미검증.
- [x] Expo Go가 아닌 커스텀 Android APK로 네이티브 모듈과 백그라운드 푸시 작업을 포함한다. 최종 소스로 preview APK 재빌드 완료(빌드 `2f66ac03-6500-45a3-a39e-940e0dd908ba`).
- [x] 기기 등록, 옵트인, 권한 상태, 서버 세션 revision, 실제 적용 확인 시각을 소유자별로 저장한다.
- [x] 세션 시작·휴식·재개·종료·자동 만료가 동일한 서버 상태 전이를 통해 기기 동기화를 요청한다. 기존 출석·타이머 결과는 바꾸지 않는다.
- [x] 서버는 대상 기기에 변경 신호만 보낸다. 토큰·서버 인증 정보는 웹 번들/기기 화면에 노출하지 않는다.
- [x] 웹은 `미연결 / 준비 필요 / 적용 확인 중 / 켜짐 / 꺼짐 / 확인 실패`를 구분하고 공부 버튼은 기기 동기화 실패로 막지 않는다. production 정적 자산 반영 확인; 계정별 실제 동작은 실기기 검증 대기.
- [x] 앱 재실행·로그인·권한 변경 시 서버와 기기 상태를 재조정한다. 로그아웃 시 앱 소유 규칙과 등록을 해제한다.
- [x] 전화·메신저 예외는 Android 설정 안내로 제공한다. 기종별로 허용 목록이 다를 수 있음을 설명한다.

## 8. Non-functional Requirements

- 신뢰성: 푸시는 전달 보장이 없는 깨우기 신호다. 순서 역전·중복·지연은 서버 최신 상태/revision으로 흡수하고, 적용 확인이 없으면 성공을 주장하지 않는다.
- 안전성: 앱 소유 규칙만 조작한다. 사용자의 수동 방해금지는 보존한다. 공부 세션 자체와 집중 규칙을 분리해 권한/푸시 오류가 출석·시간 기록을 망가뜨리지 않는다.
- 보안: 사용자 소유 RLS, 기기/세션 소유권 재검증, 최소한의 푸시 데이터, 서버 전용 전송 자격 증명.
- 접근성: 상태는 색상뿐 아니라 문자로 제공하고 권한 안내와 오류에 재시도 경로를 둔다.
- 배터리: 상시 위치/접근성 감시·무제한 폴링은 하지 않는다. 백그라운드 전략과 해제 지연을 실기기에서 측정한다.

## 9. Dependencies and Architecture

| 선택지 | 장점 | 제약 | 결정 |
| --- | --- | --- | --- |
| 휴대폰 앱 화면에서만 수동 전환 | 가장 단순 | 웹 중심 사용자의 PC 시작을 자동 반영하지 못함 | 제외 |
| 상시 foreground service + 실시간 연결 | 빠른 상태 수신 | 상시 알림·배터리·Android 서비스 제한 부담 | 첫 버전 제외 |
| 기존 Expo 푸시의 백그라운드 작업 + 화면 복귀 재조정 | 기존 `notification_targets` 활용, APK 범위 작음 | OS가 백그라운드 전달을 보장하지 않음 | 첫 APK 검증안 |

- 기존 경로: `apps/mobile/App.tsx`는 세션 RPC/조회, `apps/mobile/src/notifications.ts`는 Expo 푸시 토큰 등록, `study_sessions`는 서버 lease를 사용한다.
- 신규 경로(구현 시 상세 확정): 세션 전이에서 사용자별 집중 상태 revision/전달 작업 생성 → 서버 전용 전송 → 기기 최신 상태 조회/적용 → 확인 기록 → 웹 상태 표시.
- Supabase 테이블/RLS/함수/Edge와 출석 Cron의 실제 계약은 구현 전 MCP 또는 CLI로 운영·마이그레이션 상태를 확인한다. 예약 실행은 기존 출석·세션 처리와 충돌하지 않게 한다.
- Android SDK API 35/Build Tools 35/ADB/NDK는 E:에 설치했다. `apps/mobile/eas.json`의 preview APK, `android.package`, Android 전용 로컬 Expo 모듈과 백그라운드 작업을 구현했다. EAS 최종 APK 재빌드는 성공했지만 실제 설치와 웹→휴대폰 백그라운드 동기화는 별도로 검증한다.

## 10. Success Metrics / Acceptance

- Android 실제 기기에서 웹 시작 → 집중 규칙 켜짐 확인, 휴식 → 해제, 재개 → 다시 켜짐, 종료/lease 만료 → 해제를 확인한다.
- 휴대폰 수동 DND가 이미 켜져 있으면 앱의 휴식/종료 후에도 수동 DND는 유지된다.
- 권한 거부·푸시 지연·기기 오프라인에서는 세션은 정상 동작하고 웹에 `적용 확인 불가`가 나타난다.
- 푸시 중복/역순·앱 재시작·계정 전환에서도 다른 계정이나 이전 세션의 규칙이 적용되지 않는다.
- Android 버전/제조사별 최소 2종과 잠금 화면·백그라운드·강제 종료를 따로 실험하여 실제 동기화 지연과 실패를 기록한다.

## 11. Rollout Plan

1. APK 우선 계획을 작성하고 서버 상태/revision·기기 등록·권한·전송 및 회귀 테스트를 구현했다. 운영 DB/Edge도 적용했다.
2. Android 네이티브 규칙 모듈·백그라운드 수신·재조정·상태 UI와 웹 상태 UI를 구현했다.
3. 최종 소스의 직접 설치형 APK 빌드는 성공했다. 본인 기기의 시작/휴식/재개/종료·오프라인 검증은 남았다.
4. 웹 production 배포 `dpl_9dJjShEmkEqKngDzML5bMUJ3mbty`와 운영 정적 응답/JS 자산 스모크 테스트 완료. 로그인 계정의 실제 휴대폰 제어는 미검증이다.
6. Google Play 공개는 스토어 계정·정책·테스트 요건을 확인한 뒤 별도 승인으로 진행한다.

## 12. Open Questions

- Expo 개인 계정 로그인과 EAS 프로젝트 연결은 완료됐다. 실제 Android 기기의 OS 버전·제조사 및 USB 연결 여부는 실기기 검증 단계에서 확인한다.
- 기존 `notification_targets` 푸시 전송 경로의 운영 자격 증명 및 백그라운드 전달률. 실패 시 상시 연결/기기 내 수동 전환을 후속 대안으로 재평가한다.
- 전화/메신저 예외는 기본값을 앱이 정하지 않고 시스템 설정에 맡기는 안에 대한 사용자 확인.
