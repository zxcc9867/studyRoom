# PRD: Android 앱과 웹 독서실의 단일 로그인·기능 동등성

> 2026-10-01 운영 DB/Edge/웹 반영, 동일 서명 로컬 APK 설치 및 Android 16 부분 검증 완료. 6개 메뉴·재실행 단일 로그인·3D 숲·제품 카메라 영상, 사용자 회복 제출 후 시작/휴식/재개/휴식 중 재실행/종료와 122초 저장을 확인했다. 프로필/기기 시간대가 다른 실시간 일·월 집계도 수정·운영 배포(main a89ea0f) 후 오늘/10월 증가, 휴식 고정, 과거 월 선택 유지, 종료 후 서버 집계 일치를 에뮬레이터에서 확인했다. 기사 피드, 계정 전환, 실기기 상반신 감지/방해금지 및 새 EAS 링크 갱신은 남아 있다.

## 1. 문제와 목표

Android 앱의 네이티브 로그인 세션은 `AsyncStorage`에, 기술 피드·공부의 숲을 띄우는 WebView의 웹 세션은 별도 저장소에 있다. Android 16 에뮬레이터에서 앱에 로그인한 상태로 두 화면을 열면 로그인 화면이 다시 표시되는 것을 재현했다. 앱은 공부방·기술 피드·공부의 숲 3개 탭만 제공하지만 웹에는 오늘·목표·기술 피드·공부의 숲·내 페이지·설정 6개 섹션이 있다. 웹의 카메라 집중 기능도 앱에서 확인되지 않았다.

목표는 **앱에서 한 번 로그인하면 동일 계정으로 웹의 주요 화면을 재로그인 없이 이용**하고, 웹의 공부 시작·휴식·재개·회복루틴·카메라·계획·기록 흐름을 앱에서도 이용하는 것이다. 기존 Android 전용 방해금지 자동화와 백그라운드 동기화는 보존한다. 이것은 `prd-android-focus-mode.md`의 과거 '전체 웹 이식 제외' 및 'WebView 별도 로그인 허용' 결정보다 최신인 사용자 지시에 따른 범위 변경이다.

## 2. 사용자 시나리오와 완료 기준

- 앱 로그인 직후 오늘·목표·기술 피드·공부의 숲·내 페이지·설정을 하나의 앱 내 화면에서 오갈 수 있다. 각 화면에서 이메일 코드나 Google 재로그인을 요구하지 않는다.
- 같은 계정의 웹과 앱은 서버에 저장된 회복루틴, 할 일, 세션 상태를 공유한다. 휴식·재개·종료 후 타이머와 방해금지 상태가 서버 상태와 일치한다.
- 기기 시간대와 계정 프로필 시간대가 달라도 오늘·월 누적과 기본 표시 월은 프로필 지역을 따른다. 사용자가 직접 선택한 과거 월은 유지하며 DST·자정·월 경계에서도 같은 기준으로 집계한다.
- 앱에서 카메라 사용을 명시적으로 허용하면 웹과 같은 집중 감지 흐름을 사용할 수 있다. 권한을 거부해도 세션 자체는 시작·유지할 수 있고, 카메라 미적용을 명확히 표시한다.
- 로그아웃·계정 전환·토큰 만료·WebView 새로고침·앱 재실행 때 이전 계정의 화면 또는 저장 데이터가 노출되지 않는다.
- 원문 등 외부 링크는 시스템 브라우저에서 연다. 외부 출처에 앱 인증 정보가 전달되지 않는다.
- Android 16 에뮬레이터에서 인증·6개 섹션·타이머·카메라·회복루틴을 직접 확인한다. 방해금지 실제 토글은 권한이 있는 실기기에서 별도로 확인한다.

## 3. 범위와 제외

이번 구현 범위는 Android 로그인-웹 화면 연결, 단일 WebView 기반 웹 섹션 재사용, 카메라 권한/출처 제한, 네이티브 집중 모드와 웹 세션 상태의 동기화, 회귀 테스트다. 화면의 데이터 원천과 권한 검사는 기존 Supabase 서버 경로를 유지한다. 기존 학습 데이터와 마이그레이션 이력은 삭제하지 않는다.

이번 범위에서 iOS, Play Store 제출, 모든 웹 화면을 별도 React Native 화면으로 복제, OS 전체 앱 사용 차단, 전화·메신저 예외의 앱 내 변경, 브라우저 간 자동 로그인 공유는 하지 않는다. 카메라 권한을 얻지 못하거나 기기에서 지원되지 않는 경우 카메라 없는 공부 경로를 제공한다.

## 4. 인증·화면 아키텍처

### 4.1 세션의 소유자

네이티브 Supabase Auth 세션을 앱의 주 인증 상태로 유지한다. 이 세션은 Android 푸시·방해금지 백그라운드 동기화에도 사용한다. 웹은 Vercel의 신뢰된 HTTPS 출처에서만 로드하는 단일 WebView로 제공하고, 여기에 별도 웹 Supabase 세션을 만들되 사용자에게 두 번째 로그인 절차를 요구하지 않는다. 네이티브 refresh token이나 장기 access token을 WebView 저장소·URL·로그·분석 이벤트로 복사하지 않는다.

### 4.2 일회용 로그인 연결

1. 네이티브는 `auth.getUser()`로 현재 사용자를 확인한다. WebView는 인증 연결 중 보호 화면을 렌더링하지 않고 로딩 상태를 표시한다.
2. 네이티브는 현재 access token으로 새 Supabase Edge Function에 연결 티켓을 요청한다. 서버는 `auth.getUser(token)`으로 주체를 재검증하고, 서비스 역할 키를 서버에서만 사용하여 **그 사용자 계정의** 일회용 이메일 로그인 토큰 해시를 발급한다. 응답 사용자 ID가 요청 주체와 다른 경우 발급을 거절한다. 이메일 계정이 없거나 발급이 불가능한 경우 성공으로 위장하지 않고 재시도/지원 오류를 표시한다.
3. 네이티브는 허용한 첫 번째 출처의 최상위 WebView 문서에만 짧은 수명의 일회용 토큰 해시와 요청 식별자를 전달한다. URL, query, fragment, Android 로그에는 싣지 않는다. 외부 링크·서브프레임·다른 출처에는 전달하지 않는다. 서버는 `generateLink({type: 'magiclink'})`를 사용하며 웹은 동일한 종류의 `verifyOtp({ token_hash, type: 'magiclink' })`로 토큰을 한 번 교환한다. 재시도 시 이전 토큰을 재사용하지 않고 새 티켓을 요청한다.
4. 웹은 검증된 사용자 ID를 네이티브가 기대하는 사용자 ID와 비교한 뒤에만 보호 화면을 표시한다. 계정이 다르면 웹 저장소 세션을 삭제하고 연결을 실패 처리한다. 네이티브 로그아웃·계정 변경 때 WebView를 비우고 웹 세션을 제거한다. 웹 로그아웃도 네이티브에 통지하여 양쪽을 함께 종료한다.
5. 웹 세션이 만료되거나 인증 응답이 실패하면 보호 화면을 숨기고 연결을 다시 수행한다. 실패 화면에는 '앱 로그인 연결을 다시 시도'만 제공하고 별도 Google/코드 로그인을 정상 경로로 노출하지 않는다.

Edge Function은 네이티브 앱의 Bearer 인증만 받고 브라우저용 CORS를 열지 않는다. 인증, 오용 방지, 최소 오류 메시지, 사용자별 5분당 10회 발급 제한을 적용한다. 로그인 토큰과 인증 응답을 로그에 남기지 않는다. 로컬 테스트는 계정 일치·실패 처리를 검증했고, 실제 Supabase Auth의 동일 사용자·일회성 교환은 운영 적용 전 통합 확인이 남아 있다. 이 경로가 증명되지 않으면 출시하지 않는다.

### 4.3 웹 셸과 네이티브 기능

기존 두 개의 독립 WebView 대신 신뢰 출처의 웹 앱을 한 번 띄워 웹의 6개 섹션 탐색을 재사용한다. 오늘 화면의 할 일·타이머·회복루틴은 웹에서 기존 서버 API를 사용한다. 섹션 전환은 같은 WebView 세션을 유지해 리로드와 재인증을 피한다. 앱이 웹 세션의 시작·휴식·재개·종료 신호를 받으면 네이티브 집중 모드 코드는 **신호의 내용을 권위로 사용하지 않고** 서버 최신 세션/기기 상태를 다시 조회해 적용한다. 앱 복귀·푸시 수신 때도 기존 서버 재조회 경로를 사용한다. 방해금지 설정/권한 안내는 웹 셸에서 찾을 수 있는 네이티브 진입점으로 보존한다.

## 5. 카메라와 콘텐츠 보안

웹의 `getUserMedia`가 Android WebView에서 동작하도록 `CAMERA` 선언, 명시적 런타임 권한 요청, 거부/철회 상태를 추가한다. 카메라 스트림은 기존 웹 로직처럼 브라우저/기기 안에서 사용하고 서버로 영상 자체를 전송하지 않는다.

현재 `react-native-webview` Android 구현은 OS 카메라 권한이 있으면 WebView의 비디오 캡처 요청을 승인할 수 있으므로, 앱은 **요청 출처가 정확한 신뢰된 웹 출처이고 비디오 캡처만 요청한 경우에만** 허용하는 네이티브 정책을 추가해야 한다. 다른 출처·서브프레임·오디오·알 수 없는 리소스는 거부한다. 신뢰 출처 검사가 플랫폼 수준에서 증명되지 않으면 카메라를 활성화한 APK를 배포하지 않는다. WebView는 HTTPS·허용 출처만 앱 내부에 남기고 원문 외부 링크는 시스템 브라우저로 보낸다.

## 6. 실패·경합 처리

- 연결 중 로딩만 보이고 보호 화면이나 이전 사용자 정보는 숨긴다. 네트워크 장애에는 동일 화면에서 재시도한다.
- 시작/재개 직전에 회복루틴 요구가 새로 생긴 경우 기존 서버 시작 RPC의 응답을 기준으로 목록을 재조회하고, 회복 완료 후 재시도한다. 화면에 오래 머물렀던 경우도 같다.
- WebView가 재생성되거나 앱이 백그라운드에서 돌아오면 사용자 ID·서버 세션을 다시 확인한다. 권한/집중 모드 실패는 공부 세션을 중단시키지 않는다.
- 중복 메시지/버튼 입력은 기존 서버 멱등성·상태 전이를 따른다. WebView 메시지만으로 출석, 공부시간 또는 방해금지 상태를 확정하지 않는다.
- 계정 전환 중 이전 웹 저장소가 잠시라도 표시되지 않도록 WebView 키/저장소 경계를 사용자 ID에 묶고 새 인증이 완료될 때까지 콘텐츠를 가린다.

## 7. 검증·출시

1. 티켓 발급의 무인증/다른 사용자/중복 교환/만료/오류를 Edge 통합 테스트로 확인한다. 로그·URL·외부 출처에 토큰이 없는지 검사한다.
2. 웹 임베드 모드의 초기 로딩, 같은 계정 자동 로그인, 만료 재연결, 로그아웃, 계정 전환을 테스트한다. 일반 데스크톱 웹 로그인은 그대로 유지한다.
3. 모바일 단위 테스트와 `mobile:check`, 전체 테스트, 웹 빌드를 실행한다. Android 빌드 후 에뮬레이터에서 6개 섹션, 피드·숲 재로그인 없음, 회복루틴·세션 시작/휴식/재개/종료, 카메라 허용/거부 및 외부 링크를 직접 검증한다.
4. 서버 함수 → 웹 → Android APK 순서로 단계적으로 제공한다. 오래된 APK와 기존 웹이 새 함수 없이도 동작하도록 추가형 변경을 우선한다. 출시 전에는 새 로그인 연결을 소유자 계정에서 먼저 검증하고 실패하면 모바일 웹 셸 기능을 중지하되 기존 네이티브 공부·집중 모드와 학습 데이터는 보존한다.
5. 실제 기기의 방해금지 토글·카메라·푸시 검증은 에뮬레이터 검증과 구분해 기록한다. 성공하지 못한 기능을 '웹과 동일하게 동작'한다고 보고하지 않는다.
