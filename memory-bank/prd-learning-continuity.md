# PRD: 다음 시작점과 오늘의 학습 결과

## 1. Problem
공부를 다시 시작할 때 정확한 위치를 잊고, 시간 기록만으로 실제 남긴 내용을 보기 어렵다. 기존 회고에 note/next_action이 있으므로 별도 작성 체계를 추가하지 않는다.

## 2. Target Users
여러 할 일을 번갈아 공부하며 PC 웹·Windows·Android에서 같은 기록을 사용하는 등록 사용자.

## 3. Goals
- 기존 시작 위젯·종료 회고·오늘 기록 탭 안에서 시작점과 결과를 연결한다.
- 할 일 A와 B의 시작점을 분리하고 다른 공부를 선택해도 A를 보존한다.
- 사용자 작성 결과와 기존 유효 공부시간을 구분해 보여준다.

## 4. Non-goals
새 전역 탭, 별도 결과 작성 시스템, AI 성과 추론, 파일 업로드, 로컬 별도 학습 DB, 영상 공유, 할 일 자동 생성/완료, 출석/카메라/회복 정책 변경.

## 5. User Stories
- 이전 할 일의 정확한 위치에서 이어가거나 다른 할 일을 자유롭게 선택한다.
- 종료 시 선택적으로 결과와 다음 시작점을 한 번만 작성한다.
- 기록 탭에서 오늘 직접 남긴 결과를 확인하고 같은 회고를 수정한다.

## 6. User Scenarios
### Normal Flow
1. 집중 탭 시작 위젯은 가장 최근 이용 가능한 할 일의 시작점을 추천한다. 다른 할 일 선택은 기존 선택창을 연다.
2. 선택한 할 일의 북마크만 표시하며 회복·카메라·실제 공부 시작/일정 확인 게이트는 그대로다.
3. 종료 회고 기본 화면에는 오늘 남긴 것(note)·다음 시작점(next_action)만 있고 자료 URL/위치와 상태·할 일 완료는 접힌다.
4. 명시 저장 시 기존 회고 한 행과 세션 종료를 원자적으로 저장한다. 상태 점수를 입력하지 않았다면 임의3점/0점을 만들지 않는다.
5. 기록 탭의 단일 결과 카드는 같은 회고를 읽는다. 공부일/시간은 기존 세션 local_date/정산값을 사용한다.
### Edge Cases
- 북마크/결과 없음: 기존 시작 동작 유지·큰 빈 결과 카드 추가 안 함.
- 다른 할 일로 전환: 이전 할 일 시작점은 삭제하거나 덮어쓰지 않는다. 같은 할 일의 최신 빈 시작점은 오래된 값을 부활시키지 않는다.
- 지난날 미완료 할 일: 사용자가 승인한 일정 변경 확인에서 기존/오늘 날짜를 보여준다. 명시 확인 뒤 같은 할 일 ID의 날짜만 오늘로 옮기고 원래 계획 snapshot/공부 구간/회고는 보존한다. 미래 일정·완료/삭제 항목은 자동 이동하지 않는다.
- 여러 할 일 세션: 현재 집중할 일을 기본 연결하고 회고에서 해당 세션에 연결된 할 일 중 선택할 수 있다.
- 옛 회고 note는 memo로 보존한다. 마이그레이션이 이를 학습 결과로 변환하지 않는다.
### Error Cases
- 조회 실패는 0건으로 위장하지 않고 새 기능 영역의 재시도를 제공한다. 기존 공부 제어는 유지한다.
- 저장 실패/시간 초과는 초안·현재 공부·기한을 보존하고 서버 상태를 재조회해 불확실한 중복 종료를 막는다.
- 계정/세션 변경 뒤 늦은 응답은 새 화면/초안을 덮어쓰지 않는다.
- 이전 APK/EXE는 hosted 공통 화면을 사용하며 native 계약/설치파일을 변경하지 않는다.

## 7. Functional Requirements
- [x] 기존 reflection에 선택적 context_todo_id, 자료 URL/위치, note_kind 메타데이터만 추가하고 note/next_action을 재사용한다 (remote20261105074906 적용·기존8종 무결성 동일).
- [x] focus_score/energy_score의 미입력 null을 지원하고 평균 계산에서 null/잘못된 점수를 제외한다.
- [x] 소유/완료 세션·해당 세션 할 일 연결을 검증하는 RPC로 새 메타데이터를 저장한다. 기존 complete_study_session 서명/구형 caller는 유지한다.
- [x] 새 완료 RPC는 기존 종료/실제 공부 정산을 호출하는 한 트랜잭션으로만 확장한다.
- [x] 할 일별 최신 회고를 먼저 고른 뒤 빈 시작점을 제외한다. 제목이 같은 다른 할 일을 합치지 않는다 (snapshot·공통 UI 연결 검증).
- [x] 결과는 note_kind=learning_result이며 실제 작성 note가 있는 회고만 표시한다. 수정은 같은 행에 적용한다.
- [x] 기존 결과/시작점 수정은 확인했던 updated_at과 같을 때만 저장한다. 다른 기기에서 바뀌면 초안을 보존하고 다시 확인하도록 한다.
- [x] HTTP(S) 자료 링크/160자 위치는 선택 입력이며 unsafe scheme·과다 길이·타 계정 ID를 거부한다.
- [x] Today의 별도 전역 다음 행동 카드와 시작 위젯의 중복 표시를 제거한다. 북마크 시작과 다른 할 일 선택은 같은 제어 위치에 둔다.
- [x] 시작점 선택만으로 새 할 일 제목 자동 채움·생성·일정 이동·공부 시작을 수행하지 않는다.

## 8. Non-functional Requirements
- 기존 기록 일괄 UPDATE/DELETE·백필 없음. 원격 적용 전후 기존 열의 count/digest와 핵심 권한/정책을 대조한다.
- RLS 소유자 격리, 최소 권한, 보안 invoker wrapper, 명시 소유자 필터, 무비밀 프론트엔드.
- 375/1440px·라이트/다크·200% 글자·44px 조작 영역·키보드/초점·접힘 초안 보존.
- 새 SDK/네이티브 의존성·유료 서비스/서버 추가 없음.
- 지난 할 일 날짜 이동은 짧은 세션 쓰기 잠금으로 동시 시작을 막고, 기존 todo 잠금과 경합하면 NOWAIT로 원자 취소한다. 자동 반복 요청 없이 재시도 안내를 제공한다. 단일 연결 PGlite는 실제 다중 연결 경합을 입증하지 못하므로 이 한계를 출시 검증에 명시한다.

## 11. Rollout Plan
- 추가 호환 migration → 신규 UI. 구형 RPC는 유지하고 새 기능 조회 실패가 기존 dashboard를 막지 않게 한다.
- 롤백은 이전 웹 배포로 복귀하되 확장 schema/새 기록은 보존하는 방식이다. 이미 저장된 자료/시작점을 지우는 DROP·옛 NOT NULL 강제·과거 행 복원은 하지 않는다. DB 수정이 필요하면 검토한 forward migration을 별도로 만든다.
- 실제 계정 데이터는 임의 작성하지 않고 합성 테스트를 사용한다. 실제 앱 재로드/종료는 유휴·초안 확인 승인을 새로 받는다.
- 새 APK/EXE 없이 공통 hosted UI로 출시하고 운영 확인 결과를 별도 문서에 기록한다.
- 운영 DB local20261104153953→remote20261105074906/learning_continuity 적용. 사용자 동의하에 원문 없는 count/digest8종 일치, 기존6함수·ACL/RLS/policy/trigger 동일, 신규5RPC/private2권한 검증. 실제 건수·지문은 Git에 공개하지 않는다. 신규 FK색인 INFO2건/미사용 신설색인 INFO1건은 규모별 성능 수용 후속으로 남긴다. 상세: [검증 기록](../docs/verification/2026-11-05-learning-continuity.md).
