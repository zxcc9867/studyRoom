# PRD: 공부 시작 출석과 하루 목표 분리

갱신: 2026-10-25. 사용자 요청은 그날 공부를 시작했으면 출석으로 인정하고, 4시간 목표 달성 여부는 따로 관리하는 것이다. 이 문서가 이전의 알림 후 30분·완료 목표 대체 출석 규칙을 대체한다.

## 동작 계약

- 공부일은 기존처럼 프로필 시간대의 04:00부터 다음 날 04:00 직전까지다. 유효하게 시작한 세션은 저장된 `local_date` 공부일의 출석을 즉시 `present`로 만든다. 알림 전 종료·알림 후 시작·목표 미달도 출석이다.
- 시작하지 않은 현재 공부일은 `pending`이다. 공부일이 끝난 뒤에도 시작 기록이 없을 때만 `missed`와 출석 회복 요청을 생성한다. 시작할 수 있는 날 중간에 회복으로 잠그지 않는다.
- 예약 작업이 중단됐다가 재개되면 이미 존재하는 종료된 `pending`도 최종화한다. 이미 확정한 과거 출석·결석을 다시 판정하거나 누락된 모든 과거 날짜를 새로 만들지는 않는다.
- 평일 2시간·주말 4시간은 별도 하루 공부 목표다. 인정 시간·휴식·카메라 제외·숲/습관 보상은 기존 계산을 유지하며 목표 미달을 결석으로 바꾸지 않는다.
- 정시 초기 알림과 15분 뒤 재안내는 유지한다. 이미 출석이면 재안내하지 않는다. 채널 안내에는 30분 내 시작 의무나 목표 달성으로 출석을 복구한다는 설명을 쓰지 않는다.
- 자정이나 04:00을 넘겨 계속하는 세션은 시작 공부일 한 곳에 귀속된다. 다음 공부일의 출석으로 중복 인정하지 않는다. 날짜만 있는 할 일은 기존 달력 날짜를 유지한다.
- 인증·소유권·RLS·실제 공부 확인·카메라·세션 유지·팀 기여·중복 시작 방지와 정당한 과거/카메라 회복 잠금은 유지한다.

## 전환과 데이터 보존

- 적용 시 각 사용자의 현재 공부일만 재계산한다. 유효 시작이 있으면 출석, 아직 없으면 대기다. 과거 출석 결과와 세션 시간·할 일·회고를 일괄 재작성하지 않는다.
- 이전 규칙으로 현재 공부일에 생성한 미제출 출석 회복을 시스템 해제한다. 사용자 사유나 보충 할 일을 만들지 않고 `submitted`로 가장하지 않는다. `resolved`·해제 시각·사유로 남긴다.
- 여러 날을 포함한 미제출 회복은 현재 공부일을 제외하고 실제 남은 과거 결석의 범위/개수를 유지한다. 제출된 회복과 카메라 회복은 변경하지 않는다.
- 운영 적용은 실제 migration·권한 검증 후 진행한다. 먼저 기존 스키마에 호환되는 회복 생성/Slack 제출 RPC를 추가하고 두 Edge 함수를 배포한다. 이전 실행 요청이 종료한 뒤 정책·현재 공부일 정정 migration을 적용하고 웹을 배포한다. 온라인 Android WebView에는 같은 정책을 적용하며, native 대체 화면 문구는 다음 APK에 포함한다.

## 수용 기준

1. 일요일 오전에 2시간 공부 후 종료해도 출석 완료, 하루 목표는 2/4시간이다.
2. 공부일 내 첫 시작은 알림 전·30분 이후·03:59에도 즉시 출석이다. 세션 0건이면 04:00 전 대기, 이후 전날 결석이다.
3. 서울·도쿄·서머타임 지역의 공부일 경계를 지키며 미래/다른 공부일의 시작으로 출석하지 않는다.
4. 같은 요청/Cron을 반복해도 중복 출석·회복·발송을 만들지 않는다. 출석은 목표 미달로 하락하지 않는다.
5. 적용 전후 학습 기록이 같고, 현재 공부일의 잘못된 회복만 해제한다. 과거/카메라 회복과 사용자 간 격리를 유지한다.
6. 실제 React 합성 화면에서 출석과 목표 진척을 구분하고, README 3개 언어의 설명·스크린샷을 갱신한다. 검증·운영 반영 증거는 별도 출시 기록에 남긴다.
