# PRD: Android 앱 내부 APK 업데이트

## 2026-10-08 승인된 변경 — 버전별 업데이트 내용

- 사용자 ‘진행해줘’로 설치 방법이 아닌 해당 버전의 실제 기능 추가·개선·오류 수정 요약을 표시하는 방식을 승인했다.
- 업데이트 창의 최신 버전·출시일 아래에 ‘이번 업데이트 내용’을 독립 구역으로 표시하고 다운로드 전에 읽을 수 있게 한다. 변경사항 본문은 기본 텍스트 색상을 사용한다.
- `releaseNotes`는 해당 공개 버전에서 실제 변경된 내용만 `[추가]`·`[개선]`·`[수정]` 중 해당하는 표기로 짧게 작성한다. 반복되는 로그인 보존·설치 방법·제한 안내를 변경사항으로 채우지 않는다. 배포 대상 코드와 검증 결과를 근거로 작성하며 미포함 AI 수정 등은 넣지 않는다.
- 일반 설치 주의사항은 별도 ‘설치 안내’ 구역에 둔다. 변경사항이 없으면 ‘이 버전의 변경 내용이 아직 제공되지 않았어요.’를 표시하며 임의로 생성하지 않는다.
- 기존 공개0.2.3/code6의 출시 요약과 고정 설치 페이지는 실제 기기 단위 제한 수정 내용으로 바로잡는다. JSON 스키마·APK 파일/해시/버전·설치 동작은 바꾸지 않는다.
- 문구만 갱신하면 기존 updater 앱이 최신 출시 정보를 다시 확인해 읽을 수 있다. 네이티브 제목·구획 변경은 새 APK 설치 이후에 적용된다. 새 APK 공개는 별도 확인을 요청했으며 승인 전 기존 공개6 파일을 교체하거나 같은 빌드로 재게시하지 않는다.

## 2026-10-06 승인된 변경 — 기기 단위 설치 제한

- 사용자 ‘기기단위로 제한을 수정해줘’ 승인으로 기존 계정 전체 활성 세션 차단을 대체한다. PC만 공부 중이고 이 휴대폰은 실행하지 않으면 PC 세션을 변경하지 않고 설치를 허용한다.
- 이 휴대폰의 공부 시작/재개/전환, 카메라 사용, 준비 중 작업은 설치를 차단한다. 카메라만 끄거나 새로고침했다고 참여 기록을 지우지 않는다. 확정된 참여 세션의 휴식/종료를 확인한 경우에만 해제한다.
- 설치 직전 서버의 현재 소유자 세션과 신뢰된 최상위 WebView의 현재 실행 상태를 함께 검증한다. 조회 실패·불명 상태·구형 연결·계정/문서/탭 경합은 설치 보류다. 네이티브 fallback의 활성 세션은 실행 여부를 증명할 수 없으므로 보류한다.
- 로컬 실행 전 작은 영속 준비 잠금을 쓰고 확인한다. 서버 확정 전 pending 잠금은 새로고침 뒤 아직 없음/휴식 상태의 스냅샷으로 해제하지 않는다. 세션 ID 저장 실패/이전 문서의 preparing은 불명 상태로 보존한다. 같은 문서에서 실행 없이 취소됐음을 확인한 카메라 준비만 해제한다.
- 업데이트 확인·다운로드는 공부 중에도 가능하다. updater는 공부를 자동 휴식/종료/재개하지 않고 DB·출석·집중 모드 정책과 APK 검증·Android 설치 확인을 유지한다.
- 후보는 0.2.3/code6, 기존 패키지/서명이다. 공개 APK5/고정 설치 주소의 원본은 새 게시 승인 전 유지한다. 기기 단위 제한은 새 APK 설치 후 적용되며 웹 배포만으로 기존 APK의 설치 gate가 바뀌지는 않는다.
- AI 일일 요약 공급자 오류는 별도 미수정 이슈이며 이번 범위에 포함하지 않는다.

## 1. Problem

APK 변경 때마다 사용자가 새 링크를 찾고 브라우저에서 파일을 받아야 한다. 앱 내부에서 설치된 버전과 검증된 최신 게시 버전을 비교하고 직접 업데이트를 시작할 수 있어야 한다. 웹 화면 배포와 네이티브 APK 업데이트를 혼동하지 않도록 한다.

## 2. Target Users

- Google Play가 아닌 고정 다운로드 페이지로 독서실 APK를 설치한 Android 사용자.
- 현재 우선 검증 환경은 Android 16 에뮬레이터이며, 실휴대폰 제조사별 설치 화면은 별도 검증한다.
- iOS와 웹 브라우저에는 네이티브 APK 설치 동작을 제공하지 않는다.

## 3. Goals

- 앱 실행 중 새 버전 확인, 변경 내용 확인, 사용자 선택에 따른 다운로드·설치 화면 진입을 제공한다.
- 기존 패키지·서명을 유지하고 앱 삭제나 저장 데이터 초기화를 하지 않는다.
- 버전 판별은 날짜나 표시 문자열이 아닌 실제 설치 APK의 `versionCode`로 수행한다.
- 실패·취소·권한 거부가 로그인과 공부 기능을 막지 않도록 한다.

## 4. Non-goals

- 사용자 확인 없는 설치, 설치 권한 자동 허용, 강제 업데이트, 백그라운드 자동 다운로드.
- Expo OTA, Play Store 제출, 앱 스토어 자동 업데이트.
- 다른 앱 설치, 임의 URL 다운로드, 키 교체, Supabase DB·RLS·인증 변경.
- 공부 세션 자동 종료·자동 휴식·자동 재개, 방해금지 정책 변경.

## 5. User Stories

- 사용자는 앱에서 현재 버전과 최신 버전, 변경 내용을 보고 업데이트 여부를 선택한다.
- 사용자는 한 번의 업데이트 버튼으로 파일 다운로드를 시작하고 진행 상태를 확인한다.
- 설치 권한이 없으면 목적 설명을 읽고 직접 Android의 이 앱 출처 허용 화면을 연다.
- 권한 설정에서 돌아온 뒤 명시적으로 설치 계속하기를 눌러 Android 설치 확인 화면을 연다.
- 다운로드·설치 취소나 오류가 있으면 현재 버전으로 계속 공부한다.

## 6. User Scenarios

### Normal Flow

1. 앱 시작 시 설치된 패키지의 실제 versionName/versionCode를 읽고 고정 HTTPS 출시 정보를 한 번 조회한다. 조회 실패해도 기존 화면을 사용한다.
2. 앱 상단의 상시 업데이트 안내 없이 로그인 후 공통 `설정` 탭, 로그인 전 작은 `설정` 진입점에서 현재 버전·업데이트 상태를 확인한다. 업데이트 창에서 최신 버전·출시일·변경 내용·다운로드 크기를 확인한다. 기존 모든 메뉴는 설정의 내 페이지/화면 구성 링크를 포함해 유지한다.
3. 사용자가 `업데이트 다운로드`를 누르면 앱 전용 비공개 캐시에 내려받는다. 진행률·취소·실패/재시도를 표시하며 중복 다운로드는 합치거나 차단한다.
4. 크기·SHA256·APK 패키지·버전·서명을 검증한 파일만 설치 후보로 확정한다.
5. `업데이트 설치`를 누르면 이 휴대폰의 실행 상태와 현재 계정의 서버 세션을 재확인한다. 이 휴대폰에서 진행 중인 공부/카메라/준비 작업은 기존 휴식/종료 후 설치하도록 안내한다. PC 단독 공부는 유지하며 설치할 수 있다. 조회/기기 증명이 불명확하면 설치를 미루고 공부 상태를 임의 변경하지 않는다.
6. 출처 설치 권한이 없으면 사용자 선택으로 이 앱의 Android 설정을 연다. 복귀만으로 설치·카메라·공부를 자동 시작하지 않는다.
7. 사용자가 설치를 다시 선택하면 제한된 content URI 읽기 권한으로 Android 설치 확인 화면을 연다. 화면을 열었다는 이유로 업데이트 성공을 표시하지 않는다.
8. 다음 앱 실행/복귀에서 실제 설치 버전이 목표 빌드 이상인지 확인하고 성공을 판단한다. 같으면 미완료 상태로 다시 설치하거나 나중에 할 수 있다.

### Edge Cases

- 같은/더 낮은 최신 versionCode: 업데이트를 제안하지 않으며 강제 다운그레이드를 하지 않는다.
- 다운로드 도중 새 버전 게시: 시작 때 받은 immutable artifact URL·해시·크기·빌드 번호를 한 묶음으로 고정한다. 고정 APK 별칭이 변경돼도 다른 파일을 잘못 설치하지 않는다.
- 앱 종료/기기 재부팅/캐시 정리: 부분 파일은 설치하지 않는다. 재시도 시 새로 내려받고 이미 받은 완전 파일도 설치 직전에 재검증한다.
- 로그인 실패/로그아웃/계정 전환: 출시 정보는 공개 정보이며 인증 토큰을 요구하거나 전송하지 않는다. 공부 상태 확인은 현재 계정 경계를 따른다.
- 기기 관리자·제조사 보안 정책이 설치를 차단: 설정 우회나 앱 삭제를 지시하지 않고 이유와 고정 설치 안내 링크를 제공한다.

### Error Cases

- 오프라인/타임아웃/잘못된 출시 JSON: 확인 실패·다시 확인. 최신이라고 잘못 단정하지 않는다.
- 저장 공간 부족/응답 크기 초과/취소/해시·서명·패키지 불일치: 해당 부분/실패 파일만 삭제하고 설치를 금지한다.
- 설치 화면을 열 수 없음/권한 거부/설치 취소: 현재 앱과 로그인 데이터를 유지하고 다시 시도·나중에 선택을 제공한다.

## 7. Functional Requirements / 상세 설계

### 7.1 방식 선택

- 승인 방식: 기존 무료 로컬/EAS APK 빌드, 공개 GitHub Releases APK 보관과 고정 Vercel 주소의 출시 JSON을 사용한다. Expo 로컬 Android 모듈에서 다운로드·검증·설치 진입을 제공한다. 기존 서버 데이터 구조는 바꾸지 않는다.
- 대안 A: 앱에서 고정 다운로드 페이지만 외부 브라우저로 연다. 구현량은 적지만 앱 내부 다운로드·설치 상태를 제공하지 못하므로 승인한 요구사항의 대체안으로 사용하지 않는다.
- 대안 B: Expo OTA와 APK 업데이트를 함께 추가한다. 네이티브 권한 변경은 여전히 APK가 필요하며 별도 런타임/채널 설계가 생기므로 이번 범위에서 제외한다.

### 7.2 출시 정보 계약

- 읽기 전용 공개 `GET https://study-room-attendance.vercel.app/download/android-release.json`을 제공한다. 인증·쿠키·사용자 데이터는 필요 없다. `Cache-Control: no-store`를 설정한다.
- `schemaVersion`: 1. 알 수 없는 schema는 지원하지 않음으로 처리한다.
- `packageName`: 고정 `com.jini9867.studyroomattendance`.
- `versionName`: 사용자 표시 문자열, 최대 32자. 비교 기준으로 사용하지 않는다.
- `versionCode`: 1 이상 Android 지원 범위의 정수. 모든 공개 APK에서 단조 증가시킨다.
- `releasedAt`: 시간대가 명시된 유효 ISO8601 출시 시각. 네이티브와 맞춰 시0..23/분·초0..59, 선택 소수 초1..9자리로 검증한다. UI는 연도 포함 현지 날짜를 표시한다.
- `releaseNotes`: 일반 텍스트 배열, 최대 8항목/항목당 200자. 항목은 공백만으로 구성되지 않아야 하며 항목이 없는 배열은 허용한다. 게시 도구·JS·네이티브 검증을 일치시킨다. HTML·외부 명령으로 실행하지 않는다.
- `apkUrl`: 검증된 `https://github.com/zxcc9867/studyRoom/releases/download/<tag>/<filename>.apk` 공개 release 주소. query·인증 정보·fragment·다른 프로토콜/호스트/저장소는 거부한다. 다운로드 리디렉션은 정확한 github.com과 release-assets.githubusercontent.com HTTPS 호스트만 최대 5회 허용한다. CDN의 서명된 query는 다운로드 전용 리디렉션에서만 허용하며 기록/문서/서버 manifest에 저장하지 않는다. 와일드카드 전체 허용은 하지 않는다. 같은 tag/파일은 다른 APK로 덮어쓰지 않는다.
- `sha256`: 완성 APK의 64자리 16진수 SHA256.
- `sizeBytes`: 1 이상 150MiB 이하 정수. 다운로드 한도는 이 값과 전역 150MiB를 모두 적용한다.
- JSON 최대 16KiB, 확인 전체 제한 시간 12초. 성공 응답만 검증하며 실패 결과를 최신 버전으로 캐시하지 않는다.
- `/download/android`, `/download/android.apk`는 기존 주소를 유지한다. 앱은 게시 경합을 피하려고 출시 JSON의 immutable artifact 주소를 다운로드한다.

### 7.3 컴포넌트와 책임

- `appUpdate.ts`: 출시 JSON 검증, 비교, 네이티브 경계 호출과 오류 정규화. 날짜·설정의 버전 값을 실제 설치 버전으로 대신하지 않는다.
- `AppUpdatePanel.tsx`: 기존 mobilePalette에 맞는 작은 안내/공통 업데이트 모달. 버전·변경 내용·진행률·권한/설치 상태를 표시한다. 명시적 버튼 외 설치를 실행하지 않는다.
- `StudyAppUpdateModule.kt`: 기존 로컬 Expo 모듈에 독립 등록한다. 집중 모드 구현과 별도 책임으로 설치 버전 조회, 제한 다운로드, APK 검증, 설정/설치 화면 진입을 담당한다. 파일 경로나 임의 설치 intent를 JS 입력으로 받지 않는다.
- 별도 `StudyAppUpdateFileProvider`와 제한된 XML cache path는 updater 전용 폴더만 노출한다. exported=false와 URI별 임시 읽기 권한을 사용하고 외부 저장소·전체 cache root를 노출하지 않는다.
- `App.tsx`: 로그인 전후 같은 업데이트 상태를 유지하고 설정에서 업데이트 창을 연다. WebView 브리지는 설정 정보 조회/네이티브 창 열기만 추가한다. 다운로드/설치 명령을 받지 않으며 외부 원문·iframe에서 설정 진입도 호출할 수 없다.
- 웹 출시 JSON·기존 안내 페이지·APK redirect는 같은 게시 변경 단위로 관리한다. 후보 APK 검증 전에는 운영 최신 버전으로 게시하지 않는다.

### 7.4 네이티브 안전성 / 상태

- 공개 고정 manifest와 허용한 HTTPS artifact만 사용한다. 리디렉션마다 스킴·호스트를 검사하고 횟수/접속/읽기/전체 다운로드 시간을 제한한다.
- 다운로드는 UI 스레드 밖에서 단일 작업으로 수행하고 150MiB·디스크 용량·취소를 검사한다. 진행률은 제한된 빈도로 전달한다. 토큰·기기 ID·계정 정보를 요청/로그에 넣지 않는다.
- 다운로드 중 `.part` 파일과 검증 완료 파일을 분리한다. SHA256과 정확한 byte 수를 확인한 뒤 PackageManager로 패키지·versionCode·설치된 앱의 서명 인증서 일치를 검증한다. 이번 범위에서 인증서 회전/새 서명은 허용하지 않는다.
- 설치 직전 실제 설치 버전과 파일 해시·APK 정보를 다시 확인한다. 검증된 파일에만 일시 읽기 content URI를 발급한다.
- 필요한 `REQUEST_INSTALL_PACKAGES`는 새 APK에 선언한다. 실제 출처 허용은 사용자가 Android 설정에서 선택하며 `canRequestPackageInstalls()`로 다시 확인한다.
- 확인/다운로드/검증/권한 필요/설치 준비/설치 확인 대기/실패/최신 상태를 구분한다. 화면 진입만으로 설치 성공을 기록하지 않는다.
- 다운로드 취소/실패 파일, 이전 버전 설치 후 남은 파일, 24시간 지난 updater 파일만 정리한다. 사용자 로그인·다른 캐시·기존 학습 데이터를 지우지 않는다.

### 7.5 배포 버전

- 표시 버전은 첫 updater 출시를 0.2.0으로 올리고, `android.versionCode`는 현재 공개 APK보다 큰 값으로 관리한다.
- EAS와 로컬 빌드가 일치하도록 eas.json의 local 버전 원천과 app.json의 명시적 versionCode를 사용한다. 공개 게시 전 실제 APK의 버전·서명을 다시 추출하여 JSON과 대조한다. 같은 versionCode의 새 공개 빌드를 재게시하지 않는다.
- 기존 패키지와 서명키는 유지한다. 서명키·Google 서비스 키·환경 비밀은 아카이브 검사와 비공개 경로 정책을 따른다.

## 8. Non-functional Requirements

- 성능: 확인은 시작 시 1회와 수동 버튼으로만 진행한다. 백그라운드 반복 확인/다운로드는 없다. 실패가 웹 셸과 로그인 로딩을 지연시키지 않는다.
- 보안: HTTPS 출처·APK 무결성·동일 서명·패키지/빌드 검사를 JS와 네이티브 경계에 적용한다. 파일 공유 최소 권한, 토큰 미전송, 다운그레이드 금지.
- 접근성: 버튼 44dp 이상, 스크린리더 이름/disabled/busy/진행 상태, 글자 확대·스크롤 가능한 모달·닫기/뒤로가기를 제공한다. 한글 안내와 기존 가독성 토큰을 유지한다.
- 확장성: 공개 출시 JSON schema를 명시하고 새로운 필드나 차기 배포 채널은 별도 결정한다.
- 유지보수성: 네이티브 설치 책임을 집중 모드에서 분리하고 현재 단위·mounted 테스트/Gradle/에뮬레이터 검증 패턴을 재사용한다.

2. 순수 출시 검증/비교와 실제 RN 컴포넌트 동작을 실패 테스트부터 구현한다. 네이티브 URL/파일 검사·권한·중복/취소 흐름을 테스트한다.
3. 전체 테스트, mobile:check, 웹 build, docs:check, Android Gradle/manifest/APK 검사와 현재 카메라·집중 설정 복귀 회귀를 실행한다. 실제 검증과 mock을 구분한다.
4. 같은 서명의 구버전 updater 테스트 빌드와 더 높은 최종 빌드를 이용해 Android16에서 OS 출처 안내·취소·설치 화면·삭제 없는 업데이트·로그인 유지·실제 버전 증가를 확인한다. 테스트 전용 버전을 운영 최신 정보로 위장하지 않는다.
5. 최종 동일 서명 로컬 release APK 또는 무료 EAS preview APK의 빌드 성공·공개 GitHub Release 다운로드·크기/SHA256·패키지·실제 버전·기존 서명을 확인한 뒤 출시 JSON/고정 링크/안내를 함께 웹 production에 게시한다. Actions 성공·Vercel READY·운영 HTTP/JSON/실제 APK가 일치해야 완료로 보고한다.
6. 기존 사용자는 updater-enabled APK를 최초 한 번 고정 페이지에서 수동 업데이트한다. 이후 공개 새 버전은 앱에서 시작한다. OS 설치 승인은 매번 필요하며 무인 자동 업데이트로 설명하지 않는다.
7. 실패 시 출시 정보 제공을 중지하거나 안내만 제공한다. 이미 높은 빌드를 설치한 기기에 낮은 빌드를 업데이트로 제안하지 않는다. 복구 릴리스는 이전 검증 소스라도 더 높은 빌드 번호로 다시 서명·검증한다.

## 조사 근거

- 현재 코드: apps/mobile/app.json은 version0.1.0이며 명시적 android.versionCode가 없다. 기존 로컬 모듈의 Android manifest에는 출처 설치 권한/업데이트 파일 provider가 없고, mobile 의존성·src에 updater 흐름이 없다. apps/mobile/App.tsx의 로그인/단일 웹 셸과 기존 FocusStatusPanel을 확인했다.
- 이전 공개 APK versionCode1·동일 서명/설치 검증은 기존 implementation-plan/active-context에 기록돼 있다. 새 릴리스에서는 실제 APK로 다시 확인하며 문서만으로 판정하지 않는다.
- [Android 대체 배포와 출처별 설치 허용](https://developer.android.com/distribute/marketing-tools/alternative-distribution): 사이트 APK 배포와 Android8 이상 출처별 사용자 허용.
- [Android FileProvider](https://developer.android.com/reference/androidx/core/content/FileProvider): 제한된 파일 경로·exported=false·일시 content URI 읽기 권한.
- [Expo 앱 버전 관리](https://docs.expo.dev/build-reference/app-versions/): 표시 versionName과 Android versionCode 분리, local/remote 원천 및 실제 네이티브 버전 읽기.
