# PRD: Flexible Weekly Start Goal

## 1. Problem

최근 7일 숲길은 공부 리듬을 보여 주지만, 사용자가 지금 어느 정도면 충분한지와 다음 행동을 바로 판단하기 어렵다. 매일 연속 기록만 강조하면 하루를 쉬었을 때 전체 습관이 실패한 것처럼 느낄 수 있고, 기록을 확인한 뒤 실제 공부 시작 버튼까지 이동하는 마찰도 남는다.

## 2. Target Users

매일 완벽하게 공부하기보다 일주일에 여러 번 작은 시작을 반복하면서 휴식 여백도 지키고 싶은 개인 학습자.

## 3. Goals

- 최근 7일 중 5번 10분 시작을 기본 유연 목표로 제시한다.
- 이틀의 휴식 여백이 있다는 점을 명확히 알려 완벽주의 압박을 줄인다.
- 목표 진행도와 남은 시작 횟수를 한눈에 보여 준다.
- 오늘 단계에 맞는 문맥을 최상단 단일 시작 액션에 반영해 관찰을 즉시 행동으로 연결한다.
- 목표를 이미 채운 사용자가 오늘 쉬어도 기록이 실패하지 않는다고 안내한다.

## 4. Non-goals

- 출석 `present`/`missed`, 평일 2시간·주말 4시간 목표 또는 10분 습관 성공 기준 변경.
- 5회 미달에 대한 감점, 경고색, 연속 기록 초기화 또는 보상 회수.
- 이번 단계에서 사용자별 목표 횟수 설정, 새 DB 컬럼, 새 RPC 또는 Expo 화면 추가.
- 최상단 버튼의 `10분 시작 준비` 문맥이 10분 뒤 세션을 자동 종료하는 타이머로 동작하는 것.

## 5. User Stories

- As a learner, I want a five-of-seven target, so that I can rest without treating the week as failed.
- As a learner, I want to know how many starts remain, so that the weekly path gives me a clear next step.
- As a learner, I want the habit card context to flow into one topbar start action, so that insight becomes action with less friction.

## 6. User Scenarios

### Normal Flow

1. 사용자는 최근 7일 숲길에서 5개 씨앗 표지판의 진행도를 확인한다.
2. 5회 미만이면 `5번 시작까지 N번`과 이틀 휴식 안내를 본다.
3. 오늘 10분 미만이면 최상단 단일 시작 액션이 `10분 시작 준비`, 10분 이상이지만 일일 목표 미만이면 `오늘 목표 이어가기`로 표시되며 사용자는 그 버튼을 누른다.
4. 최근 다음 행동이 있으면 우선 제안하고, 없으면 첫 번째 오늘 미완료 todo를 미리 선택한다.
5. 회복 루틴, 카메라 준비, todo 선택을 모두 통과한 뒤 사용자가 직접 세션을 시작한다.

### Edge Cases

- 5회 이상 시작했다면 진행도는 5/5로 고정하고 오늘 휴식도 허용하는 문구를 표시한다.
- 오늘 일일 목표를 이미 달성했다면 주간 카드가 추가 시작 액션을 만들지 않고 최상단 버튼은 다른 문맥 우선순위 또는 기본 라벨을 따른다.
- 활성 또는 휴식 세션 중이면 주간 시작 안내를 숨기고 최상단 버튼은 `잠시 쉬기` 또는 `공부 계속하기`로 전환한다.
- 최근 다음 행동과 오늘 todo가 모두 없으면 기존 todo 빠른 추가 화면을 빈 상태로 연다.
- 시작 성공 일수가 5회를 넘더라도 데이터는 그대로 유지하고 표시만 목표 상한으로 제한한다.

### Error Cases

- 최상단 시작 액션 이후 회복 또는 카메라 안내를 취소하면 기존 제안 정리 규칙을 그대로 적용한다.
- 세션 시작이나 todo 추가 실패는 기존 대시보드 오류 메시지로 표시한다.

## 7. Functional Requirements

- [x] 기본 목표 5회와 휴식 여백 2일을 결정적 상수로 정의한다.
- [x] 목표 달성 여부, 남은 시작 횟수, 0~100% 진행도를 helper에서 계산한다.
- [x] 목표 달성 후 오늘 미시작 상태를 실패가 아닌 선택 가능한 휴식으로 안내한다.
- [x] 5개 씨앗 마커로 목표 진행도를 표시하고 접근 가능한 progressbar 정보를 제공한다.
- [x] 오늘 단계에 따라 최상단 단일 시작 액션에 `10분 시작 준비` 또는 `오늘 목표 이어가기` 라벨을 반영한다.
- [x] 최상단 단일 시작 액션이 최근 다음 행동 또는 첫 번째 오늘 미완료 todo를 기존 세션 시작 흐름에 전달한다.
- [x] 모바일에서 목표 표지판과 비대화형 안내가 한 열로 재배치되고 가로 overflow가 없다.

## 8. Non-functional Requirements

- 성능: 기존 `weeklyHabitRhythm` 결과와 메모리의 todo만 사용하며 네트워크 요청을 추가하지 않는다.
- 보안: 기존 사용자별 RLS 데이터와 세션 시작 RPC만 사용한다.
- 접근성: 목표 이름·현재값·최댓값을 텍스트와 ARIA 속성으로 제공하고 최상단 단일 시작 액션에 명확한 이름을 제공한다.
- 확장성: 기본 목표 횟수와 상태 계산을 React 밖에 두어 후속 사용자 설정에 대비한다.
- 유지보수성: 세션 시작 게이트를 복제하지 않고 기존 `startTimer()` 경로를 재사용한다.

## 9. Dependencies

- 내부 의존성: `weeklyHabit.mjs`, `dailyHabit.mjs`, `sessionTodos.mjs`, 기존 `startTimer()` 흐름.
- 외부 의존성: React, 기존 Lucide 아이콘.
- Supabase: 기존 조회 데이터와 세션 시작 RPC만 사용하며 변경 없음.
- API: 추가 없음.
- 환경 변수: 추가 없음.

## 10. Success Metrics

- 0·4·5·7회 시작에서 남은 횟수와 진행도가 정확하다.
- 목표를 이미 채운 오늘 미시작 상태에서 휴식 허용 문구가 표시된다.
- 최상단 단일 시작 액션이 최근 다음 행동 또는 첫 미완료 todo를 기존 게이트에 전달한다.
- 1440px와 390px에서 표지판·마커·비대화형 안내에 overflow가 없다.
- 전체 테스트와 production build가 통과한다.

## 11. Rollout Plan

- 개발: helper 상태와 코칭 테스트를 먼저 추가하고 목표 표지판을 최상단 단일 시작 액션에 연결한다.
- 테스트: 목표 경계, 단일 시작 액션 source contract, 전체 테스트, build, 실제 Chrome 반응형 검증을 수행한다.
- 배포: 사용자가 명시적으로 요청할 때 기존 GitHub Actions/Vercel 경로를 사용한다.
- 모니터링: 실제 사용에서 5회 목표 달성률과 최상단 단일 시작 액션을 통한 시작 비율을 관찰한다.

## 12. Open Questions

- 5회 목표를 사용자별 3~7회로 조정할 수 있게 할지는 사용 데이터 확인 후 결정한다.
- 목표 달성은 `prd-weekly-forest-reward.md`의 누적 반딧불 화환으로 연결했다. 화환 수에 따른 추가 섬 구역 해금은 사용 데이터 확인 후 결정한다.
