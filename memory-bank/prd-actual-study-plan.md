## 8. Integration compatibility clarification

기존 활성/휴식 세션에 연결된 미완료 할 일이 없더라도 재개가 막히지 않아야 한다. 오늘의 소유한 미완료 할 일을 선택하거나 제목만 새로 만들고 집중 대상으로 지정할 수 있다. 기존 연결과 과거 배분 미확인은 보존하며, 새 연결은 일정 조정·재개/전환 확정과 같은 트랜잭션에서만 추가한다. 미리보기 취소 시 연결·세션·시간표를 변경하지 않는다. 일반적인 재개는 기존 연결 목록을 그대로 사용한다.

# PRD: 실제 공부와 계획을 연결하는 세션 UX

## 1. Problem / Target Users

계획 시각과 실제 공부 시각이 달라졌을 때 원래 계획을 덮어쓰면 지연과 휴식 이력을 잃는다. 시간표를 사용하는 독서실 이용자가 지금 하는 공부와 남은 분량을 이해할 수 있어야 한다.

## 2. Goals

- 원래 계획, 현재 조정 일정, 실제 공부 구간을 별도로 저장한다.
- 기존 이번 세션 할 일 패널에서 현재 집중할 일 하나와 접힌 다음 할 일을 표시한다.
- 늦은 시작과 재개 시 남은 분량을 제안하며 최초 시작 지연만 평가한다.
- 충돌하는 일정 전체의 전후 시간을 미리 보여주고 수락 시 세션 동작과 함께 원자적으로 적용한다.
- 기존 공부 성과와 계획 준수를 분리하고 공부시간, 출석, 숲 보상을 감점하지 않는다.

## 3. Non-goals

- 과거 세션 시간을 할 일에 임의 배분하지 않는다.
- 목표 분량 도달 시 자동 종료/완료하지 않는다.
- Expo 새 화면, 반복 규칙 자동 변경, 새로운 벌점/회복루틴은 만들지 않는다.

## 4. Functional Requirements

- 제목 필수, 시간 선택. 시간이 있으면 최초 구간 길이가 목표 분량이다. 시간이 없으면 임의 남은 시간/종료를 만들지 않는다.
- 하나 선택 시 현재 할 일 자동 지정, 여러 개 선택 시 첫 집중할 일을 고른다.
- 시작/재개 버튼이 충돌 없는 제안의 확인 역할을 한다. 충돌 시만 변경 모달을 추가한다.
- 16~18시 계획을 18시 처음 시작하면 2시간 지연 및 18~20시 조정. 16시 시작 후 30분 공부/휴식/18시 재개이면 누적 30분을 유지하고 90분만 제안한다.
- 현재 할 일 제목/상태, 실제 시작/재개, 누적/남은 시간, 조정 일정, 원래 계획 순으로 표시한다. 휴식 중 진행도는 멈춘다.
- 일정 연쇄 이동은 시간순으로 충돌만 최소 이동하며 분량과 비충돌 여유를 보존한다. 완료한 할 일과 실제 공부 구간은 이동하지 않는다.
- 자정 넘김은 날짜를 보여주고 다음 날 충돌까지 검사한다. 완전한 변경 목록을 계산할 수 없으면 확정하지 않는다.
- 취소는 무변경. 다른 기기 변경은 이전 확인을 무효화하고 새 제안을 보여준다.
- 원래 일정/목표, 변경 이력, 세션/할 일 연결 실제 구간은 서버 저장. 사용자당 열린 구간 최대 하나.
- 시작/휴식/재개/전환/종료/만료와 카메라 제외를 반영하고 할 일 인정 시간 합은 세션 인정 시간 이하이다.
- 미리보기/확정 API 분리, 서버 시각/소유권/상태/일정 버전 재검증, 단일 트랜잭션, 요청 UUID 멱등성, 소유자 RLS.
- 기존 API 호출은 호환 유지. 정확한 이전 배분이 없으면 이전 공부시간 배분 미확인을 표시한다.
- 리포트는 최초 지연, 계획대로 시작한 비율, 조정 횟수, 시작하지 못한 계획을 표시한다. 시간 미지정과 측정 도입 전 과거 날짜는 평가하지 않는다.
- 기술 피드 하이라이트는 기존 요약 호출 한 번으로 최대 3개 실제 글을 선정하며 출처 검증/캐시/근거 부족 시 생략을 유지한다.

## 5. Dependencies / Security

기존 Vite React, Supabase sessions/todos/links/presence, 카메라/휴식/만료 정책을 유지한다. 소유권을 서버에서 검증하고 인증된 사용자의 직접 시간 위조를 허용하지 않는다.
