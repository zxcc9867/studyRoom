# PRD: 새벽 4시 공부일과 세션 귀속

## 1. Problem / Target Users

- 밤늦게 공부하는 사용자의 한 세션이 자정에 나뉘어 출석 목표와 하루 기록이 어긋난다.
- 기존 달력 날짜 기반 집계를 이번 사용자가 승인한 공부일 정책으로 개정한다.

## 2. Goals / User Scenarios

- 프로필 시간대의 04:00에 새 공부일이 시작된다. 04:00 미만의 새 세션은 전날 공부일이다.
- 진행 중 세션은 종료될 때까지 저장된 시작 공부일에 전체 인정 시간을 귀속한다. 휴식·카메라 제외·만료 정책은 유지한다.
- 2026-10-05 23:00~10-06 01:30은 10-05에 9,000초, 10-06에 0초다. 평일 2시간 목표를 충족한다.
- 날짜·월·시간대 변경, 휴식 후 재개에도 이미 저장된 세션 공부일은 바꾸지 않는다.

## 3. Requirements / Non-goals

- 출석, 오늘 누적, 기간 리포트, 습관·숲 보상에 같은 세션 귀속을 적용한다.
- 원래 계획의 날짜·시각, 기술 피드의 날짜, AI 일일 한도는 달력 날짜를 유지한다.
- 새벽에는 전날 공부일의 할 일과 실제 달력 날짜의 할 일을 모두 선택할 수 있다. 예: 10-06 01:00 계획을 01:00에 시작해도 계획은 10-06 그대로, 세션 출석 귀속은 10-05다.
- 기존 세션의 local_date 값과 출석 결과를 일괄 재작성하지 않는다. 과거 기간 조회는 저장된 날짜 기준 전체 세션 집계로 달라질 수 있다.
- 실제 공부 구간과 목표 계획 준수는 유지하며 새 보상·감점을 만들지 않는다.
- API 시그니처, 인증·소유권·RLS·중복 요청 방지를 보존한다.
- 출석 알림의 15분 재안내·30분 마감 기록은 알림이 시작한 공부일을 유지한다. 04:00 이후 새로 시작하는 세션은 새 공부일이므로 전날 알림 출석을 소급 인정하지 않는다.

## 4. Dependencies / Rollout / Success Metrics

- 공유 날짜 헬퍼, React 대시보드, 기존 Supabase 시작·미리보기·집계 RPC.
- 경계/DST·자정/월말·휴식·재개·소유권의 실제 SQL/JS 회귀 테스트 후 DB → 웹 배포.
- 같은 세션의 두 날짜 중복 인정이 없고, 기존 2시간/4시간 출석 기준을 유지한다.
- 모바일의 기본 WebView도 동일 배포 웹과 서버를 사용한다. 네이티브 비상 대체 화면 변경은 새 APK에 포함해야 한다.
